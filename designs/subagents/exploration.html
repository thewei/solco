Design Storybook · Sub-agent views

One model, five surfaces

A sub-agent is one read-only record — id · provider · type · description · status · started/ended · last line · result — read from the provider's own files. Every surface below draws that same record; none invents state.

  • Chat card replaces the plain Delegated … tool row: live line while it runs, a 3-line result when it ends, Open to drill in. Several at once become one roster.
  • Drawer is the drill-down: the child's own transcript, read-only, beside the chat (full-width page in a narrow window).
  • Sidebar / Header popover nest under the parent: running ones show, finished ones sink into N done. The popover gets no fifth tab — a Working parent carries a badge and its children.
  • Tasks tray keeps plan items and sub-agents as two sections of one tray; they are not matched by text.
  • Degraded: unreadable layout → the plain tool row, nothing else changes.

Status uses the one indicator: spinner = running, hollow ring = finished, amber/red dot = stopped/failed. Counts in the header trigger stay waiting/total of addressable agents — sub-agents are not.
