Design Storybook
Variants
Interaction states

Automations：herdr 自动化的原生视图

决策点：侧栏第 5 个视图目的地的信息架构（A 列表+抽屉 / B 看板 / C 双栏监控），以及 Agent 起草→人审批的创建流如何进入界面。

调研结论（Phase 0）

  • 参考 DnzzL/herdr-automations（MIT，已克隆 /tmp）：herdr 插件 + 常驻 daemon，cron 触发，每次运行开真实 worktree workspace + agent start/prompt/wait；缺口 = 无草稿审批、无成功通知、历史无界、无清理 TTL、只留 pane id。
  • 业界共识（ChatGPT Tasks / Claude Code routines）：任务 = prompt+触发+环境，Agent 可对话式创建，每次运行可追溯，有专门管理面。
  • solco 已有插件门控先例（internal/workboard）与本机自有插件先例（com.whstudio.solco.hooks）；workboard 亦有项目级 automations 客户端。

三案共同点：视图入口在 sidebarViewTabs 第 6 枚图标（⌘6），gate 关时隐藏；Agent 起草的自动化一律先落「草稿/待审阅」，批准才启用；每次运行在真实窗格，可从运行行跳窗格或经 internal/history 在 Chat 回看；提示词与 Agent 分析（rationale）一起保存。

取舍

  • A：与 Sessions/Files 心智一致、实现最薄；活感靠列表行内 spinner + 抽屉。
  • B：监控感最强，「需要你」列统一收口失败与待审；密度最低，自动化多时靠滚动。
  • C：单自动化生命周期最完整（RunStrip 阶段条）；占宽最大，多一层选择。

最脆弱的假设：插件 v1 只有 cron/一次性/手动触发，「事件触发」用轮询近似（草稿卡里已向用户言明）；daemon 挂掉时视图只读 + 顶部离线提示。

视觉：全部色值取自 internal/nativeui/theme.go（暗色）；行高/圆角对齐 controls.go 与既有视图。
