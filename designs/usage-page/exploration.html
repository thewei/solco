调研：独立额度 App 怎么做

对标 CodexBar（steipete，91+ 家）、ClaudeBar（tddworks，开源 SwiftUI）、UsageNow（本地优先）。共同形态：

  • 每家 = 若干「窗口」：5 小时 / 周 / 月 / 额外用量；每个窗口 = 已用% + 重置倒计时，两者缺一不可。
  • 节奏（pace）：条上一根刻度 = 此刻「均匀消耗」应在的位置；超过它就是「会提前耗尽」。CodexBar 叫 even-use guide，ClaudeBar 叫 Forecast。
  • 诚实的缺省：拿不到就写「未上报」，不编造；陈旧数据带「N 分钟前 / App 未运行」标记（UsageNow 原则）。
  • 两层数据：「额度」（供应商端）与「活动」（本机日志的 token / 30 天条）分开呈现。
  • 凭据哲学：优先零凭据路径（Codex app-server、Antigravity 本地服务）；必须读时只读不改不刷新、token 进 Keychain、只发往供应商自己的主机。

本机实测（只读探针）

  • Codex 0.164：codex app-server 的 account/rateLimits/read 零凭据可用——5h 0%、周 19%、plan=plus，另有 1 张重置券。原型里 Codex 卡用的就是这组真实数值。
  • Claude Code：Keychain 有 Claude Code-credentials，但 ~/.claude/settings.json 把 BASE_URL 指向 127.0.0.1:3425——账号额度端点对它无意义，要有「自定义端点」态。
  • Cursor：agent CLI 没有 usage 子命令；额度在 cursor.com，需 token（Settings 里给）。
  • Antigravity.app 已装但未运行：额度来自它运行时的 127.0.0.1 本地服务 → 需要「未运行」陈旧态。
  • gh 已登录 → Copilot 可借 gh 登录，不必另贴 token。

落点（Phase 4，定稿后）

侧栏 history_scope.go historyNav 加 Usage 行；新路由页 page_usage.go；新域包 internal/usage（探针 + 缓存，零 UI）；Settings 加 /settings/usage；token 走 MyGo mygo.Secrets（Keychain，≤2560B）。
