设计规则

优先级：attention > review > working > idle。图标颜色 + title 只反映最高优先级状态。 Attention/Review → 橙色图标 + N；Working → 绿色图标 + N；Idle → 银色图标 + 无文字。 Disconnected → 红色空心图标 + 无文字。Tooltip 始终显示完整状态。
优点最省空间；颜色一眼分出紧急度；数字不需要解释
缺点非 template icon（彩色），深浅色菜单栏下需两种渲染；丢失多维度并列信息
方案 B · N/M 需要你比总数（比例）
标题格式 N/M，N = 需要你（attention + review），M = 总 agent 数。图标始终 logo 单色。

设计规则

N = NeedsAttention + ReviewPending（合并为"需要你"）。M = 所有已列出 agent 的总数。 图标保持 template（单色，无状态色），大小恒定。Disconnected → title 变为 — 或空。
优点保持 template icon；比例感清晰（5 分之 2 需要我）；用户提到的 "1/2" 格式
缺点N/M 的含义需要 tooltip 解释；M 在 agent 全部退出时可能为 0
方案 C · 双状态紧凑（最多 2 组）
保留两组最关键的状态：需要你 N + 工作 M。去掉 Review 和 Attention 的区分。

设计规则

Attention 和 Review 合并为 ⚠N（都需要用户介入）。Working 独立为 ⚡M。 最多显示两组，超过两组时丢弃低优先级组。Idle → 无文字。Disconnected → tooltip 降级，title 空。
优点保留现有符号习惯；比现有 3 组少 1 组；简化 mental model（needs you vs working）
缺点仍然有符号+数字；比 A/B 稍宽；Review 和 Attention 混在一起可能不够精确
方案对比
宽度含义清晰度图标macOS 原生度实现复杂度
现有最宽（⚠ 2 ✓ 1 ⚡ 3）3 维度并列，但符号多终端框高（template + text）最低
A · 状态色 + 数最窄（1 个数字）颜色编码紧急度，数字是数量盘羊 logo · 彩色中（非 template）中（需渲染多色 PNG）
B · N/M 比例窄（0/5）比例清晰，但 N 含义需 tooltip盘羊 logo · template高低（只改 title）
C · 双组紧凑中（⚠2 ⚡3）2 维度，比 3 组简化盘羊 logo · template高最低（改 title 合并）
个人推荐：方案 A。理由：空间最省，颜色是最强的 preattentive signal——你不需要读数字就知道有事。配合 tooltip 获取完整状态，信息不丢失。缺点是放弃 template，需要自己管理浅色/深色菜单栏的 icon 渲染。如果不想放弃 template icon，方案 B 是最实用的退路。
