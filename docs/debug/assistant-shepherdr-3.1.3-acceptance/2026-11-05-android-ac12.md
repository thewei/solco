# AC-12 (phone half) — Android reads the same Assistant core as the Mac

Device: vivo V2309A (USB adb), release APK built from solco-mobile HEAD (72 MB, arm64-v8a, installed with `-r`, data kept). Host: isolated SolcoAcc.app (Local network, 192.168.5.72:7791, its own certificate) over a sandbox Herdr + OMP fixture + plugin core. Paired by delivering the app's own `solco://pair?…` link (Settings → Remote Access → Pair a Phone → Copy Link) to the phone as a VIEW intent. The pairing code was single-use and is not recorded here.

| Step | Observed (screenshots beside this file) |
|---|---|
| Pair | Phone shows `Wilson-MacBook-Pro.local · LAN`, Connected |
| ⋯ menu | `Assistants` and `Automations` are offered only because the Host advertised `personalAgent` |
| Assistants list | `Ada · Idle` — an Assistant created by CLI on the Mac, so the phone reads the Mac's store, not its own (U03) |
| Coding task filed on the Mac | Phone's Ada page: Solco record `Task filed` → `Run settled`, **Needs you: Phone feature — Ready for your review** (Open / Got it) |
| Open | Shared Chat page on the task's real Herdr pane: the real OMP session ("Committed feature.txt on the task branch.", the shell command row) |
| Review started + rejected on the Mac (CLI) | Within ~6 s the phone's Solco record shows `Verifying … is ready` then `Run settled · review … is rejected`; the Needs-you card is gone — the same newest-fact behaviour the 8c882eff fix gives the desktop |

## Not covered

Approve/Accept/Reject from the phone (the phone page has Open / Got it only), phone push delivery (U04: needs a registered device token + OS notification receipt), disconnect/reconnect cursor recovery, Memory/Routines/Autonomy screens, and any flow while the Mac is asleep. AC-12 stays open.

## Side effect to undo

The phone's host book now also holds this isolated Mac (same display name as the real one, different certificate; it is unreachable once the rig is stopped). Remove it in Connection settings if it shows up as a second card.
